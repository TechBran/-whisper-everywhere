# QNN 2.50, the v0.63.0 pack refresh, and the 8gen1 family: the measurement sheet

**Result.** All twelve packs (six families x two tiers) passed every gate of
`tools/build_asset_packs.py measure` at Qualcomm AI Hub release **v0.63.0**, and a second run
reproduced every row from the pasted literals: `measure OK: all 12 rows reproduce the embedded
24-digest census exactly`. v0.63.0 is a **rebuild** with QAIRT 2.50.0.260828221209, not a
re-release. None of the twenty 0.62.2 digests reproduces. Every encoder is 11.5-22.1% smaller,
every decoder moved by under 0.06%, and the graph IO census is **equal to `NpuModelSpec` on all
twelve**. The sixth family, `8gen1` (SM8450, HTP v69, soc_model 36), passed the same gates for
both tiers.

**What was measured.** On 2026-09-24, on the MS-02 (Linux, python 3.12), from the branch's own
`tools/build_asset_packs.py` copied to `~/qnn250/`, into a **fresh** workspace
(`~/.androidbuild/fleet-packs-v0.63.0`). The workspace had to be fresh: the vendor zip basenames
carry no release (the version lives in the URL's directory), and the tool's download cache keys on
basename and exact length. A 0.62.2 zip of the same length would have been hashed as 0.63.0 bytes.
Here every length moved, so the old cache would also have been re-downloaded. The fresh workspace
makes that a fact rather than a coincidence. Logs: run 1 (record mode, exit 2 by design) and
run 2 (reproduce, exit 0).

**What was NOT measured.** Any execution. No v0.63.0 binary has run on AI Hub or on a device, and
no v69 binary has run anywhere in this program. See §8.

## 7. What the refresh does on a phone that already has a pair

`isInstalled` gates the files on disk against the device family's census bytes at ±5%. The 0.62.2
turbo encoder on the Fold6 is 775,831,552 B, against the new row's 686,112,520 (+13.1%); the
S23 Ultra's is the same (+13.1%); a small encoder from 0.62.2 is +17.5%. So after updating to 4.15
the NPU tier reads as **not installed**, and the chooser offers the fetch again, until the v0.63.0
pack is downloaded. That is how the new binaries reach an existing install, and on an 8 Gen 3 it
costs the user the turbo pair again: 981,968,552 B installed, and about 824 MB over the wire,
because Play deflates asset packs in transit (the vendor's own zip of the same pair is
823,721,812 B; Play's real transfer size is not measured). The old context binaries would still load under 2.50 (a newer runtime reads older
contexts, which is what R7 was). They are the slow ones. `NpuFleetCensusTest` pins this fact, so a
future release that lands within ±5% of the old bytes cannot quietly keep old pairs installed.

The SAF delivery zips published on the release page (the `pack_npu_zip.py` / `delivery-zip`
outputs) are 0.61.0/0.62.2 bytes. 4.15 refuses them on import for the same reason, so they need
regenerating from the v0.63.0 zips before release.

**What 4.15 does about it (shipped on this branch; owner ruling 2026-09-24).** The re-download
stays, and it is no longer silent or wasteful. On the first launch after the update the launch
pass (`reconcileNpuStagingDebris`) removes a paired tier's files when they are on disk and fail
the device family's v0.63.0 row. The rule is `NpuStalePairSweep`, which calls the same
`passesInstalledGate` that `isInstalled` reads. The old ~1 GB pair therefore no longer sits on
disk while the new pack downloads and copies. The pass logs `npu: stale pair removed tier=npu-turbo
encoder=775831552 decoder=295854080 census=686112520/295856032` through the native `WE-DIAG` export,
which a Play build still prints. When the removed tier is the selected one, it records the
re-download in a device-local store that backup and device transfer never carry. `BootReceiver`
then posts, on a new *Model updates* channel, "Your AI-chip model has a faster version" / "One-time
download of about 824 MB. Tap to open Whisper Everywhere and get it." The size is the device family's
vendor zip. It posts once on the update, then on every boot until the pack lands, in place of the
restart notice. The onboarding flow the app opens on shows "Your AI-chip model has a faster
version — download it again (one-time)." Both disappear when a pair lands, because the shared
finalise clears the record. An off-census device keeps whatever it holds. None of this has run on a
device yet. The Fold6 and S23 Ultra checks in §8 are its first run: the line, the notice in the
shade, and the sentence on the permissions step.
