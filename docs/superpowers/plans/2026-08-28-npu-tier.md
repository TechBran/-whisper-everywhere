### The seven paid-for lessons (binding — each cost a device round trip)

1. **`<uses-native-library ... required="false"/>`** for `libcdsprpc.so` + `libadsprpc.so`.
   Without it Android 12+ refuses the FastRPC library and the HTP silently never comes up.
2. **`Qnn_Tensor_t` is not self-contained.** `name` and `dimensions` are pointers owned by the
   system context. Deep-copy everything you keep; do not free the system context early.
3. **Never `#ifdef` an enumerator.** `QNN_TENSOR_VERSION_*` are enum constants; `#ifdef` is always
   false and silently compiles the branch out.
4. **Version every versioned struct, loudly** — and, per C7 below, **verify every precondition the
   design rests on, not just the ones with a version field.**
5. **Bind by NAME, never by index.** The decoder has 51 inputs.
6. **A vote that fails silently looks exactly like slow silicon.** Report the vote result always.
7. **Own the buffers, 64-byte aligned, RAII, copy deleted.**

## Measured ground and BAKED asset facts

The spike (9 runs) settled the architecture and the numbers: encoder **404.6 ms sustained** /
369.2 burst, cold load **525 ms**, 26 ms bands, zero thermal drift. The seam is raw QNN, owned.

Everything below was parsed out of the real asset. **It is not first-contact for the
implementer** — bind against these facts, and let the load-time guards confirm them.

### Asset pair (`whisper_small_quantized-precompiled_qnn_onnx-w8a16-qualcomm_snapdragon_8gen3.zip`)

| File | Bytes | sha256 |
|---|---|---|
| `encoder_qairt_context.bin` | 132,927,488 | `3e92ac26545b6b9d22ecfab594ae57523134006e2722b09fa10e16b193e9e5ec` |
| `decoder_qairt_context.bin` | 225,316,864 | `fda23d731e6b0ab7fb0a50373a49efe2d1792faa5dad456837624d8b8e44b0e4` |

Sum **358,244,352 B = 358 MB (341.6 MiB)**. Both carry `binary_info_version 3`,
`graph_info_version 3`, tensor **v2**, blob QAIRT `v2.45.0.260326154327`, `socModel 57`
(SM8650 / HTP v75). One graph each; the encoder graph is `whisper_small_quantized_encoder`.

> **Version pairing risk (R7):** the blobs are QAIRT **2.45**, the runtime we bundle is **2.49**.
> The spike proved this pairing **for the encoder only**. The decoder binary has never been
> deserialised under 2.49 — that is the first thing Q10a confirms.

### Encoder IO (confirmed on device, spike runs 7–9)

- **in** `input_features` `ufixed16 [1,80,3000]` = 480,000 B, scale `4.677007018472068e-05`,
  zero_point `32072`
- **out** 24 × cross-KV `ufixed8`: `k_cache_cross_0..11` `[12,1,64,1500]`,
  `v_cache_cross_0..11` `[12,1,1500,64]`, 1,152,000 B each = **27,648,000 B (26.37 MiB)**

### Decoder IO — 51 inputs, 25 outputs

| Group | Count | Shape / dtype | Bytes each |
|---|---|---|---|
| `input_ids` | 1 | `int32 [1,1]` | 4 |
| `position_ids` | 1 | `int32 [1]` | 4 |
| `attention_mask` | 1 | `uint16 [1,1,1,200]` | 400 |
| `k_cache_self_N_in` | 12 | `uint8 [12,1,64,199]` | 152,832 |
| `v_cache_self_N_in` | 12 | `uint8 [12,1,199,64]` | 152,832 |
| `k/v_cache_cross_N` | 24 | `uint8`, as encoder outputs | 1,152,000 |
| **out** `logits` | 1 | `uint16 [1,51865,1,1]` | 103,730 |
| **out** `k/v_cache_self_N_out` | 24 | mirrors the `_in` shapes | 152,832 |

Total in **31,316,376 B**, total out **3,771,698 B**.

**Four consequences that shape the design:**

1. **Cross-KV is bound ONCE, never re-copied.** The decoder's 24 cross-KV inputs were verified
   pairwise identical to the encoder's outputs in shape, scale and zero_point (e.g.
   `k_cache_cross_0` scale `0.06918466091156006`, zp `128`, both sides). **Alias the same
   `AlignedBuf`s.** Re-feeding per token would move 26.4 MiB × ~100 tokens ≈ 2.6 GB per segment.
   **That equality is a plan-time observation, not a runtime fact — Q4 step 1 makes it a guard.**
2. **Self-KV ping-pongs; it is never memcpy'd.** `_in`/`_out` scales match per layer, so no
   requantisation between steps. Two sets of 24 buffers (2 × 3,667,968 = 7,335,936 B) and
   **re-bind (`tensorSetClientBuf`) each step** — 48 calls per token, negligible. QNN cannot alias
   one buffer as both input and output.
3. **The asset caps context at 200 positions.** Self-KV depth is 199 (+1 current); the mask is
   `[1,1,1,200]`. Whisper's own `max_length` of 448 is unreachable — **the asset's 200 wins**, and
   the cap is a normal terminal condition, not an error.
4. **Greedy argmax runs on the raw `uint16` logits.** Dequant is `scale × (q − zp)` with
   `scale > 0`, strictly monotonic, so argmax is preserved exactly. **But the suppression mask must
   be applied BEFORE the argmax scan** (C2) — that is why the whole loop is native.

`attention_mask` quantisation is exact: scale `0.0015259021893143654`, zp `65535` →
**attend = `65535`, masked = `0`** (`0.0015259021893143654 × −65535 = −100.0`).

### Memory budget

127 MB encoder + 215 MB decoder + 26.4 MiB cross-KV + 7.0 MiB self-KV + 0.5 MiB mel/logits ≈
**376 MiB** NPU-side residency. Tear `multi` down before arming NPU **and release NPU before
falling back to multi** (I11) — never co-resident, on either path.

## Task Q2 — The mel export: correct stride, correct frame count  **[NATIVE + SUBMODULE]**

> ⚠️ **Two-repo task, and the read-back is the subtlest thing in this plan.**
> `log_mel_spectrogram` is `static` (`src/whisper.cpp:3170`) and both `whisper_mel` (`:414`) and
> `whisper_state` (`:834`) are private to `src/whisper.cpp` — **there is no public read-back of the
> computed mel**, so the fork edit is unavoidable. Reimplementing the filterbank app-side is
> spec-forbidden ("one mel implementation in the app, ever") and would decouple NPU accuracy from
> CPU accuracy.

**The stride trap (this is why the naive version produces structured noise, not an error).**

- `whisper_mel` is **bin-major with stride `n_len`** — `:3156` and `:3164` write
  `mel.data[j * mel.n_len + i]`.
- For a 480,000-sample (30 s) input, **`mel.n_len = 6000`** (`:3206`): whisper appends 30 s of
  zeros before framing. A flat copy of the first `n_mel * 3000` floats reads bins 0–39 at wrong
  offsets and **never touches bins 40–79**.
- **`n_len_org` is 2999, not 3000** (`:3208`: `1 + (480000 + 200 − 400)/160 = 2999`). The encoder
  needs exactly 3000 columns. **Answer to the frame question: do not pad the source — zero-fill the
  destination first and copy what exists.** Column 2999 is legitimately zero, which is exactly what
  whisper's own encoder does.
- **The correct extraction already exists in-tree at `src/whisper.cpp:2382-2402`** and must be
  mirrored: `memset(dst, 0, …)`, then
  `dst[j*2*n_ctx + (i - i0)] = mel_inp.data[j*mel_inp.n_len + i]` over
  `i0 = min(mel_offset, n_len)`, `i1 = min(mel_offset + 2*n_ctx, n_len)`.

**Steps**

1. **THE ALIAS GUARD (C7) — before anything binds.** At `nativeInit`, after both graphs are
   enumerated, loop the 24 cross-KV names and assert per pair that `dataType`, rank, every
   dimension, and `quantizeParams.scaleOffsetEncoding.{scale,offset}` are **identical** between the
   encoder output and the decoder input. On mismatch, fail with a named stage string —
   `alias: k_cache_cross_7 scale 0.06918466 != 0.07030000` — routing into the loud fallback.
   *Why this is not optional:* the equality was verified by the plan's author from `metadata.json`
   at plan-writing time. If a future asset regeneration shifts one side's scale, the alias feeds
   the decoder cross-KV under the wrong affine transform. The result is not a crash and not
   garbage — it is **plausible wrong text**, the worst failure for a dictation app and the one a
   single-sentence acceptance bar is least likely to catch. Lesson 4's discipline, applied to the
   precondition the whole zero-copy design rests on.
2. **Bind by name.** Build a `map<string,int>` over all 51 inputs and 25 outputs. Never index
   positionally (lesson 5) — with 51 inputs an off-by-one is a silent wrong answer, not a crash.
3. **Cross-KV: bind once at init to the encoder's output buffers.** Zero copy, never rewritten.
4. **Self-KV: two buffer sets, swapped by re-binding** (`tensorSetClientBuf`, 48 calls/token).
   Never memcpy 3.6 MB per step; never alias one buffer as both input and output.
5. **The decode loop is NATIVE, and this is a correctness requirement, not a performance one (C2).**
   ```kotlin
   external fun nativeDecodeSegment(prompt: IntArray, suppress: IntArray, beginSuppress: IntArray,
                                    maxTokens: Int, out: IntArray): Int   // >=0 count, <0 error
   external fun nativeLastError(): String                                  // "" | "stage: detail"
   ```
   Whisper suppression is **by construction a pre-argmax mask**. A caller holding only the argmax
   has no runner-up: it can detect that the model wants a suppressed token and do nothing useful —
   re-running the step is deterministic and returns the same token, so the loop either emits the
   suppressed token or hangs. Native therefore: writes `input_ids`/`position_ids` (plain `int32`,
   un-quantised), executes, **applies the suppression mask to the logits, and only then scans for
   the argmax**.
   *(JNI crossing cost was never the issue — a two-int transition is ~100 ns against a ~4.5 ms
   `graphExecute`. The boundary was in the wrong place for correctness.)*
6. **`position` is the single counter (I2).** The four prompt tokens each consume a self-KV slot.
   Enumerate it exactly:
   - `position = 0,1,2,3` → the prompt (`SOT`, lang, `TRANSCRIBE`, `NO_TIMESTAMPS`), fed through
     the same execute path; the token emitted at `position = 3` is the **first generated token**.
   - `BEGIN_SUPPRESS` applies **only at that first generated step** (`position == promptLen - 1`),
     not at `position == 0`.
   - Terminate on `EOT` or `position >= 199` (the last writable self-KV slot). With a 4-token
     prompt that is at most 196 generated tokens.
   - `attention_mask` is filled `65535` for `0..position` and `0` above it.
7. `nativeResetDecode` is gone — `nativeDecodeSegment` owns the whole loop and zeroes both self-KV
   sets on entry. Cross-KV survives; it belongs to the current segment's encode.
8. `WhisperTokens` carries the pinned constants and the verbatim 88-entry `SUPPRESS` plus
   `BEGIN_SUPPRESS = [220, 50257]`. `MAX_POSITIONS = 200` comes from **the asset**, not from
   whisper's 448.
9. `NpuDecodePolicy` is the **config source** the native loop consumes — `promptTokens`,
   `suppressList`, `beginSuppressList`, `maxTokensFor(promptLen)`. It stays pure and fully
   JVM-tested, and its truth table now pins arrays the decoder actually uses rather than a
   post-hoc filter with no lever.

**Test (red first)**
